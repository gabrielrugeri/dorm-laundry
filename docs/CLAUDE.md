# Dorm Laundry — project guide for Claude Code

Open-source web app to book washing machines in university dormitories.
Pilot: one dormitory, 6 machines, 2-hour slots, 50 RUB per machine/slot.
Designed to be extended to other dormitories later (multi-dormitory from day one in the data model).

Read `docs/MVP-SPEC.md` before starting any task. It is the source of truth for scope.

## Stack
- Python 3.12+, Django 5.x
- SQLite in development, PostgreSQL in production
- HTMX for interactivity, Tailwind CSS compiled locally (standalone CLI), no SPA framework
- Installable PWA (manifest + service worker) for mobile use
- Django i18n (gettext): Russian (`ru`) and English (`en`) are mandatory. Every user-facing string must be translatable from the first commit.
- Tests: pytest + pytest-django

## Hard rules
1. **No external runtime dependencies in the front-end.** No CDNs, Google Fonts, Google Sign-In, reCAPTCHA, analytics or third-party scripts. Users in Russia may not reach them. Serve fonts, JS and CSS from our own server.
2. **Double-booking must be impossible at database level.** `UNIQUE(machine, date, slot)` on active bookings plus transactions on write. UI validation alone is not enough.
3. **Privacy.** Never expose a resident's name or room to other residents. The public grid shows only free/occupied (and "yours" for the logged-in resident). Names and rooms are visible only to manager and admin. No endpoint may allow looking up a resident by student code.
4. **No real personal data in the repository, ever.** Use fake seed data (`manage.py seed_demo`). Secrets live in environment variables; keep `.env.example` up to date, `.env` is gitignored.
5. **Money** is stored as integer rubles (or kopecks) in a ledger of transactions; balance is derived from the ledger, never edited directly. Every change is an auditable transaction.
6. **Time.** Store UTC, display `Europe/Moscow`. Slot definitions are data (`TimeSlot` model), not hard-coded.
7. **Multi-dormitory ready.** Machines, residents, slots and bookings belong to a `Dormitory`. All queries are scoped by dormitory.
8. **Roles:** resident, manager (keys), admin. Enforce permissions in views/queries and test them.
9. Calendar export is an `.ics` file generated by the server (works in any calendar app).
10. **Django admin (`/admin/`) is for superusers (developers) only.** Dormitory admins and managers never need it; everything they do happens in our own pages (`/manage/`, the key schedule).

## Admin UI principles
Dormitory admins are not tech-savvy. Every `/manage/` screen follows these rules:
- **Plain language only.** Russian is the default admin language. Never show technical terms (ledger, adjustment, audit event), internal ids, JSON, field names or UTC times. Use the words in [docs/GLOSSARY.md](GLOSSARY.md) and add new ones there.
- **One primary action per screen.** Secondary actions go under "More" («Ещё»). Destructive actions always need a confirmation step.
- **If an action is not allowed, its button does not exist** (not just a server-side refusal). The server still checks every action.
- **Show only what serves the admin's task.** A resident's profile answers "is this resident in good standing?" at a glance: name, room, balance (prominent), debt status, upcoming bookings, recent payments, then the main actions. Full history is collapsed.
- **Navigation: at most 5–6 top-level items.**
- Times in Moscow time, money as "150 ₽", dates as "14 октября".

## Workflow
- For each feature: propose a short plan first, wait for approval, then implement in small commits.
- Write tests for: double-booking race, consecutive-slot booking, cancellation/refund, balance ledger, role permissions, privacy (no leaking of names/rooms).
- Code, comments, commit messages and docs in English. UI strings in `ru` and `en`.
- Keep it simple and readable: other students will maintain this. Prefer boring, well-documented choices.
- Update `README.md` and `docs/` when behaviour or setup changes.

## Commands (fill in as the project grows)
- Setup: `python -m venv .venv && source .venv/bin/activate && pip install -r requirements-dev.txt` (Windows: `.venv\Scripts\activate`)
- CSS: `python scripts/tailwind.py build` (or `watch` while editing templates)
- Run: `python manage.py migrate && python manage.py seed_demo && python manage.py runserver`
- Tests: `pytest`
- Lint/format: `ruff check . && ruff format .`
- Translations: `python manage.py makemessages -l ru -l en && python scripts/check_translations.py && python manage.py compilemessages` (needs GNU gettext)
- Dependencies: edit `requirements*.in`, then `pip-compile requirements.in && pip-compile requirements-dev.in`

## Layout
- `config/settings/{base,dev,prod,test}.py`; apps live in `apps/` (`core`, `accounts`, `dorms`, `bookings`, `ledger`, `keylog`).
- Data model and the rules it enforces: `docs/ARCHITECTURE.md`.
